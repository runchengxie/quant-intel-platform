## 代码质量基线

基线为 9 个生产 Python 脚本，共 1213 行，运行时仅使用标准库。原有 45 项 Python 测试和 6 项 JavaScript 测试通过。

Python 行与分支联合覆盖率约为 75%。类型检查发现 10 处问题。48 个函数和类的平均 McCabe 复杂度为 8.56，最高的函数分别为解读生成 40、报告导入 32、解读结构校验 26。

整改关注职责拆分、数据边界和失败路径。指标用于定位难维护的代码，不通过删测试、扩大忽略规则或机械拆碎函数来降低数字。

重构后保留标准库运行时，没有新增第三方运行依赖。新增的报告准备模块只通过 CLI 调用上游，原有模块之间仍是 13 条静态导入边，没有增加业务抽象层。没有巨型类，也没有发现达到 Vulture 80% 置信度的未使用代码，因此未为减少行数删除仍在使用的入口。

LOC 增长来自统一格式、职责拆分、错误处理和新增报告准备流程，不能把它解释为代码变得更简洁。认知复杂度使用 Complexipy 8.0.1 同口径比较。最高值仍在服务错误提取与简评生成函数，后续应结合真实修改频率继续收敛，避免只为分数拆出过多函数。

`tools/audit_structure.py` 输出每个模块的 LOC、AST 节点数、本地导入边、标准库依赖和按名称可解析的直接调用边。它不追踪动态分派、方法调用和注入函数。CI 保存该报告、覆盖率 XML 和依赖审计 JSON，供以后比较。完整操作命令见 README。

生产依赖链按不可变提交记录：行情与日历由数据平台提供，报告能力由公开框架 CLI 提供，私有部署固定公开框架版本，网站由自身 PR 和 Actions 发布。报告目标日期、原始生成时间、补发时间、模型版本、提示词哈希、来源哈希与部署回执各自保留，便于追踪一个页面观点所用的材料。
