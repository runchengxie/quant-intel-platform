# Astro 日报与飞书图表整合设计

设计日期：2026-09-24。状态：设计稿，尚未实现或发布。

## 目标与边界

读者仍在 Quant 市场情报网站阅读最近五个交易日的晨报、晚报、美股日报与市场解读；晨晚报另可查看原飞书日报的六类图表，并在图上交互查看经核验的数值。保留现有暖色视觉、报告日期筛选、Markdown 原文、文本报告、图表 PNG 下载和来源链接。图表缺项、降级与历史补发必须显眼，不把旧观测值、占位图或新闻推断伪装成当日事实。

本次不合并 `quant-market-research` 与日报网站，不复制研究算法，不改变行情采集、模型写作、飞书发送或美股日报事实审核。旧飞书 PNG 继续供飞书交付；网页不把它们作为默认图表数据。生产切换、定时器和真实投递仍由各自 owner 单独验证。

现有代码把晨、晚报分别定义为六张图。前四张为综合仪表盘、资金流向、热点概念及情绪图；后两张为美股隔夜和周度概览。晚报第四张称“市场温度计”，晨报称“情绪指标图”，不能只按相同文件名混用。当前公开导入仅接收 Markdown；图片尚无公开契约。`quant-market-research` 的 Astro 静态页面、局部 React/ECharts 图表、来源/日期容器和按需加载是实现参考，不构成运行时依赖。

## 方案选择

选择 Astro 静态构建作为日报网站页面所有者：构建期输出报告正文、导航、状态与数值表；轻量脚本处理日期/晨晚报筛选；React/ECharts island 仅在图表进入视口或读者展开时加载图形与当期数据。保留现有 Python 公开快照、归档和审核逻辑，构建改为“Python 准备已审核公开快照 → Astro 构建 → 公开产物检查”。避免同时重写事实生产链路。

未选择“继续原生 JS 加六张互动图”，因为后续要维护筛选、缩放、工具提示、主题同步和图表可访问性；未选择“全部插入 PNG”，因为图像下载量随日期与图数增加，且无法提供真实数据交互。两者可分别作为迁移期间的旧页面和明确标注的单图兼容回退，不是最终默认路径。图片体积与初始资源预算须用实际产物测量，不写未经测量的节省比例。

## 图表公开契约

上游 `quant-intel-platform` 从生成原飞书图的同一份已验证输入导出**图表就绪数据**，不从 PNG 反向识别数值，不复制 owner 算法到网页。每期使用独立且不可变的 `date + kind` 身份；不能依赖会被下一次晨报或晚报覆盖的 `daily_*.png`。发布边界如下：

1. Provider 生成版本化的六图清单：报告 ID、目标交易日、晨/晚报类型、生成时间、图表键、显示名称、单位、所需序列/数值、各序列原始观测日、来源标识与可公开来源链接、质量状态、限制说明、内容哈希。每个预期图表都占一个位置，缺项仅给状态和原因，不填演示值。跨市场与周度图保留各自真实观测日期。
2. `publication: public` 只批准审过的字段与资源。私有路径、聊天目标、凭据、未经许可的原始明细及无法核实的解释不得进入公开文件。普通 `ok` 图要求数值、单位、日期、来源自洽；`degraded` 图说明实际替代数据及日期；`missing`/`skipped` 不绘图。上游只有 PNG 时可经同样审核列为 `legacy_image`，浏览器需点击才加载，并展示交易日与实际观测日；占位图不得作为 `ok` 图发布。
3. Pages 导入器核对 schema 版本、身份/日期、路径边界、哈希、状态与必填字段。图表快照按现有 `report_id = <date>-<kind>` 关联，最多跟随现有五个公开报告日期；导入先预览、再原子应用并归档旧版本。缺图不阻断报告正文发布；无效或越界的图表资源不能静默变成可见图。部署发布器仅传递清单显式允许的文件，不能广泛复制上游 `out/`。
4. 页面数据路径采用单期文件（例如 `data/charts/<date>-<kind>.json`），只在该期图表可见时请求。网页与飞书的图名允许不同，但图表键、数据口径和状态映射须有测试固定。用户切换日期或报告类型后，图、表、来源和状态必须同属所选报告。

契约字段的精确命名在 provider PR 中固定并由 consumer 契约测试引用；变更 schema 需显式迁移，不靠静默兼容。新闻归因、研究判断不作为图表数值数据混入契约。

## 页面与交互

- Astro 静态 HTML 输出首页的标题、更新时间和现有报告内容；每期独立报告页输出六图卡片与无脚本可读的数值表，避免把五日期全部图表数据塞进首页。不把全部报告放进客户端 React 状态。保留现有五日期窗口、晨晚报筛选与美股日报独立版块。现有 Markdown 表格、列表、标题及来源链接须保持等价，原始 HTML 不直接作为可信内容插入。
- 每期晨报和晚报在正文附近提供独立“六图概览”。初始展示六张卡片的名称、日期、状态与一行用途；展开或滚动到图表时才取该期 JSON 并加载 ECharts。交互先限于悬停精确值、图例切换、必要时范围缩放和查看数值表，不为每张图硬造相同交互。窄屏可纵向浏览，键盘可进入图例/明细；颜色之外仍用符号、标签和零线表达涨跌。
- 复用研究站“图表 + 单位/样本/边界/方法 + 查看数值”的信息结构，但沿用日报站暖白、赭红、金色等设计变量；正负不以绿色/红色作为唯一编码。缺项卡写明“缺项”及原因；`degraded` 卡显示实际观测日和替代来源；`legacy_image` 只在点击时加载，可下载但不称为交互图。
- 维持 GitHub Pages 的 `/market-intel-pages/` 子路径、既有报告 Markdown URL 和美股日报下载链接。主题、日期筛选与展开状态不改变数据口径。旧站构建保留到 Astro 产物和旧页面行为通过对照测试，再移除重复前端代码。

## 顺序、验收与回退

分成三个独立仓库的变更，按 provider → consumer → deploy 顺序合并：

1. `quant-intel-platform` 提供六图结构化公开候选、日期/质量校验和样例；验证晨晚报同名文件不会串期，缺数据不伪造值。
2. `market-intel-pages` 扩展显式公开导入/归档契约，建立 Astro 静态页面与按需图表；先用审核过的样例验证，再导入真实 provider 产物。比较旧新页面的近期报告、Markdown、筛选、美股日报和链接，不提前切换生产。
3. `quant-intel-deploy` 收窄发布白名单、加对应调度/回执和失败保留旧快照；只指向已合并的 provider、consumer 发布版本，切换后查实际网页与资源请求。任一环节失败时，旧网站及旧报告继续可读，图表显示缺项，不回退为未经审核的 PNG。

验收包括：schema/路径/隐私与哈希的负例测试；正常、缺项、降级、历史补发、晨晚报重名资源的契约测试；静态 HTML 在禁用 JavaScript 时可读；桌面与手机的筛选、图例、数值表、来源、主题与键盘检查；初始页面不请求六张 PNG、不下载 ECharts，图表展开后才加载所需数据；记录真实资源大小及与旧版的对比。构建、类型/单元测试、浏览器测试、公开产物扫描和适用仓库门禁通过后才能申请发布。不能把构建通过等同于数据已审核。
