# 语言与本地化规范

[English page](LANGUAGE_POLICY.md)

`quant-intel-platform` 的计算、源数据、产物 schema 和投递回执保持语言无关。
结构化报告模型生成后，人类可读报告再按指定 locale 渲染。

公共 locale 标识为 `en-US` 和 `zh-CN`。面向用户的报告和公开文档站默认使用
`en-US`。locale 与时区、货币、交易日历和数值精度相互独立。未知 locale 必须快速失败，不得静默
改变报告语义。

工程标识符、CLI 参数、JSON key、产物契约和错误码保持英文或语言无关。不要把
译文标签写入机器可读产物；渲染器只翻译展示层标签。

A 股晨报和晚报在插入来源字段前选择 locale 文案。标题、正文模板、新鲜度摘要、已知生产端标签和金额单位支持两种语言。只有属于相应生产字段的已知标签才会翻译。缺失译文时使用英文，未知 locale 会报错。

新闻陈述、标题、来源名称、证据 URL、概念名称和未知的生产端说明保留原文。英文报告会明确提示，不会自动翻译任意来源内容。locale 选择不再替换整份报告中的文字，也不修改输入 payload、计算、产物 schema 或回执身份。晨报公开发布和导入链路在两种语言下保留警告分类及上一期收盘报告的数值基准。

公开文档分别提供英文和中文导航，Pages 的路由与回退行为由其自身维护。

为新界面增加本地化时，先确定结构化报告模型的边界，再测试确定性渲染和 CLI 语言选择。以英文作为文档事实来源，为活跃公开页面维护中文版本，并按需翻译历史归档。

两种语言应共享一个报告构建器，再使用多个 locale renderer，不应维护两套独立
报告生成流程。
