# 美股收盘简报：评测与飞书接入

本文记录 quant-market-briefing、quant-intel-platform 和私有仓库 quant-intel-deploy 之间的协作方式与后续工作。公开仓库中的实现只校验发布包并生成不发送消息的预览，不会启用生产定时任务或向真实受众发送消息。

## 当前状态

quant-market-briefing 可生成五段中文播报、机器可读的观点、来源记录和 market.briefing.v1 产物，并沿用 research.platform-publication.v1 发布清单。最近一次深度试跑用 Astra xhigh 完成第一轮研究、Astra high 补查反方证据，再用 GPT-6.1 Sol medium 精修。这只是偏重质量的试验配置。单个样本发现了有用的纠错和反方材料，但不足以证明预测能力或最合适的模型配置。三次模型调用共约 30 分钟。

程序校验不能代替来源审核。briefing 文件中的 source_audit_passed 仍为 false。正式预览要求另有来源审核记录，绑定证据、分析和简报文件的哈希，并逐条批准最终文本中的所有结论。日报生成器和公开预览命令都不读取飞书接收对象、密钥或生产排程。

quant-intel-platform 已增加 market.briefing.v1 与 market.source-review.v1 的消费校验，以及本地预览命令。变更目前仍在 PR #195 中，尚未发布。预览会显示原文、标题和来源链接，不连接飞书。真实接收目标、凭据、固定的生产路径和定时任务仍由私有仓库 quant-intel-deploy 管理。

```bash
uv run dm us-briefing-preview --manifest PATH --allow-internal
```

内部发布包需要显式加上 `--allow-internal`。命令输出 `market.briefing.preview.v1` JSON，包含 `dry_run: true` 和完整预览正文，不包含目标或发送回执。

## 建议的职责与流程

1. quant-market-briefing 生成版本化报告和发布包，不导入消费端源码。
2. quant-intel-platform 校验发布清单、两种 v1 格式、文件哈希、审核与报告的绑定，以及公开或内部受众范围。
3. 公开实现目前生成不发送的预览。后续接入飞书时，再复用投递层、回执和幂等机制，发送阶段不改写正文。
4. quant-intel-deploy 负责固定生产者和消费者版本、提供私有配置，并根据已结束的美国交易日历触发任务。密钥、接收目标、报告和回执保留在公开仓库之外。

仅有通用发布清单校验还不够：消费端必须理解这两种美股报告格式，并在审核绑定或受众校验失败时停止。未经所需来源审核的草稿不能进入正式发送流程。

## 后续事项

- [ ] 在现有模型、推理强度和耗时记录旁保存实际 token 用量或其他可获得的用量指标。
- [ ] 建立可重放的评测集，冻结证据并固定提示词，对比不同模型和推理强度时不重复联网研究。
- [ ] 比较事实纠正、来源支持度、有效反方证据、方向判断清晰度、运行时间和用量。语气更强或更乐观不算预测更好。
- [ ] 保留数据的历史版本，之后用实际结果评估一至四周和六至十二个月的判断。单日样本无法证明预测准确性。

## 边界

公开 CI 可以运行契约校验、合成数据样例和离线预览测试。不能读取凭据、连接飞书、抓取实时市场数据或调度模型调用。真实投递属于后续私有部署工作，必须先确认接收范围，并具备来源审核、受众隔离、幂等回执和故障恢复能力。
