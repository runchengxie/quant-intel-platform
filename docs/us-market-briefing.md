# 美股收盘简报：评测与飞书接入

本文记录 quant-market-briefing、quant-intel-platform 和私有仓库 quant-intel-deploy 之间的后续工作。这里说明的是计划，不会启用生产定时任务，也不会授权向真实受众发送消息。

## 当前状态

quant-market-briefing 可生成五段中文播报、机器可读的观点、来源记录和 market.briefing.v1 产物，并沿用 research.platform-publication.v1 发布清单。最近一次深度试跑用 Astra xhigh 完成第一轮研究、Astra high 补查反方证据，再用 GPT-6.1 Sol medium 精修。这只是偏重质量的试验配置。单个样本发现了有用的纠错和反方材料，但不足以证明预测能力或最合适的模型配置。三次模型调用共约 30 分钟。

程序校验不能代替来源审核。只有另行生成的审核记录通过后，source_audit_passed 才能变为真。日报生成器也不知道飞书接收对象、密钥或生产排程。

quant-intel-platform 已负责报告渲染、飞书投递、回执和相关的失败关闭测试。目前还没有消费 market.briefing.v1 和 market.source-review.v1 的适配器。真实接收目标、凭据、固定的生产路径和定时任务由私有仓库 quant-intel-deploy 管理。

## 建议的职责与流程

1. quant-market-briefing 生成版本化报告和发布包，不导入消费端源码。
2. quant-intel-platform 校验发布清单、报告与来源审核格式、文件哈希、审核与报告的绑定，以及公开或内部受众范围，然后渲染五段内容。
3. 消费端将审核通过的正文交给现有飞书投递层，写入投递回执，并使用基于报告日期的稳定幂等键。
4. quant-intel-deploy 固定生产者和消费者版本，提供私有配置，并根据已结束的美国交易日历触发任务。密钥、接收目标、报告和回执保留在公开仓库之外。

仅有通用发布清单校验还不够：消费端必须理解这两种美股报告格式，并在审核绑定或受众校验失败时停止。未经所需来源审核的草稿不能进入正式发送流程。

## 后续事项

### 模型与研究评测

- [ ] 在现有模型、推理强度和耗时记录旁保存实际 token 用量或其他可获得的用量指标。
- [ ] 建立可重放的评测集，冻结证据并固定提示词，对比不同模型和推理强度时不重复联网研究。
- [ ] 比较事实纠正、来源支持度、有效反方证据、方向判断清晰度、运行时间和用量。语气更强或更乐观不算预测更好。
- [ ] 保留数据的历史版本，之后用实际结果评估一至四周和六至十二个月的判断。单日样本无法证明预测准确性。

### 飞书消费端与部署

- [ ] 为 market.briefing.v1 和 market.source-review.v1 增加消费适配器与契约样例。
- [ ] 将日报渲染为现有飞书图文格式。投递时只传送审核后的正文，不在发送阶段再次调用模型改写。
- [ ] 增加幂等和投递回执测试，覆盖重复尝试、审核未通过和缺少受众配置等情况。
- [ ] 只在 quant-intel-deploy 增加部署入口与调度配置，并明确固定版本和私有设置。
- [ ] 在考虑真实接收对象之前，先验证不发送模式、交易日历与节假日处理、失败重试和过期恢复。
- [ ] 配置生产接收目标前，确认接收对象与首次真实发送的范围。

## 边界

公开 CI 可以运行契约校验、合成数据样例、渲染测试和模拟飞书投递。不能读取凭据、连接飞书、抓取实时市场数据或调度模型调用。真实投递属于私有部署，必须先满足相应的来源审核、受众范围、幂等回执和运维恢复条件。
