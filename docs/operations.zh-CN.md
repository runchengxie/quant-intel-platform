# 运维约定

[English page](operations.md)

## 故障语义

数据不完整或外部服务不可用时，平台会记录降级状态，并在无法安全生成结果时停止后续处理。成功、降级和失败都应写入可检查的回执。

## 部署边界

主机定时任务、生产凭据、真实投递目标和运行状态由 `quant-intel-deploy` 管理。public 仓库只提供可复用的代码、契约和离线检查。

## 恢复与调度

通过稳定生产路径调用文档中的 `dm`、`a-share-daily` 和恢复脚本。定时任务不得指向临时 worktree。生产路径调整后，重新加载对应 systemd unit，并运行对应的离线或 shadow 冒烟检查。

## 质量门禁

```bash
uv run python project_tools/check_all.py --scope all
```

该入口覆盖测试、lint、类型检查、CLI 帮助同步、package coverage 和脚本检查。公开边界检查由 CI 单独运行。CI 不抓取真实市场数据，不调用飞书，也不使用券商凭据。


### 周度篮子个人投递

`a-share-daily weekly-basket --send --personal-only` 只投递到显式指定的
`--personal-chat-id`，忽略已配置的群目标，也不要求 `--group-chat-id`。
不加此选项时，必须同时指定个人和群目标。切换此选项不会重建个人回执或幂等键。

### 周度篮子投递 v2 迁移

真实发送需要 `--sender-scope`，也可通过 `WEEKLY_BASKET_SENDER_SCOPE` 提供。
该值是运维人员声明的稳定发送账户标识，用于绑定本地投递记录，并不证明外部 CLI
当前登录的账户身份。`--state-root` 必须保持稳定，规范投递状态位于其 `delivery/`
子目录；输出根目录同时用于查找旧版按日期存放的回执。改变目录不代表可以重新发送。持久化投递与渲染锁要求 POSIX 主机及支持 `flock`、
目录 `fsync` 的文件系统；不支持这些能力的主机不得承担真实投递。

文字和图片分别记录持久化结果。`sent` 表示每个要求发送的阶段都获得了 CLI 返回的
消息 ID，不代表收件人已读。响应格式错误、超时、中断时仍处于 inflight 的记录，
以及内容变化，都会暂停该次投递，不自动重试。旧回执原样保留，返回
`legacy_unverified` / `hold_no_send`，包括旧版 `failed` 和 `dry_run`。
本次不提供自动迁移或重发工具；重新开放投递前需要单独审查历史记录。

渲染返回不可变 bundle 路径及哈希清单。`report.md`、`basket.csv` 和 `report.png`
兼容路径继续供读取，但投递绑定冻结的 bundle 和私有快照，不使用后续重新渲染的文件。
试运行将输出与篮子冻结状态放入独立的 `previews/` 命名空间，返回实际文件路径，
不覆盖正式状态，但仍只读正式历史并复用本周冻结组合；显式覆盖只作用于预览状态。
消费者应读取返回路径，不再假定试运行会写入正式日期目录。

以上仅为源码契约。生产切换由 Deploy 仓负责：配置发送账户标识，保留既有状态及
历史回执根目录，并联合验证生产者和消费者版本后才能启用真实发送。
源码合并本身不授权上线或重试历史暂停记录。
