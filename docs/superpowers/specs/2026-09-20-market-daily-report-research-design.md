# 市场日报研究链路设计

## 1. 目标与边界

本设计用于生成一份接近交易台收盘简报的美股市场日报。报告需要同时覆盖市场表现、市场驱动因素、宏观数据与美联储动态、公司新闻、主要上涨个股和主要下跌个股，并为事实和解释保留来源、时间与证据。

首期目标是让日报可以按日期重放、稳定生成、追溯来源，并在数据不足时明确标出缺口。系统不输出自动交易指令，也不把大模型生成的解释当作确定事实。现有 A 股日报、市场页面和投递链路继续保留。

## 2. 仓库职责

### `quant-intel-platform`

负责数据源适配、标准化事实、事件抽取、研究任务协议、证据校验、日报渲染和本地 CLI。市场数据和报告产物通过版本化协议对外提供。

### `quant-intel-deploy`

负责生产配置、Hermes 或 systemd 调度、凭据注入、固定版本的平台发布、重试、运行记录和投递回执。部署仓库不复制平台业务代码，也不直接导入相邻仓库的源码。

### `market-intel-pages`

只消费经过校验的公开日报产物并负责页面展示。页面仓库不抓取市场数据、不拥有模型密钥、不决定事实或因果解释。

跨仓库通信使用公开 CLI、版本化 JSON 产物或稳定的 HTTP 接口。相邻仓库之间不依赖未发布的内部 Python 模块。

## 3. 数据源与首期覆盖

首期优先复用已有适配器和权限，先补齐数据字段与证据链，再决定是否采购新的供应商。

- 指数、行业、个股涨跌和公司新闻：优先使用现有 FMP、yfinance、Alpha Vantage、Twelve Data 能力。
- 美债收益率：至少覆盖 2 年、5 年、10 年和 30 年，用于判断曲线变化。优先使用美国财政部官方日度曲线或已有 FMP 能力。
- 宏观数据：使用 FRED 和已有经济日历适配器。Trading Economics 只有在凭据和权限可用时启用，缺少权限时将该部分标记为降级。
- 美联储：使用官方讲话、声明、会议材料和 RSS，模型只负责提取和归纳。
- 公司公告：使用 SEC EDGAR、公司公告和已有新闻接口交叉验证。
- 跨市场：补齐美元指数、USDJPY、黄金、白银、WTI 和比特币期货或现货的现有可用代理，并记录标的定义。
- 期权到期、CTA、BofA、GS 等卖方研究：首期不通过公开搜索猜测原始观点。后续通过研究邮箱或 PDF 入口导入已获得授权的材料。

每日任务必须保留截至时间。收盘后才出现的修订或新闻不能回写到收盘时点之前的报告。

## 4. 产物协议

所有产物包含 `schema_version`、`as_of`、`generated_at`、`run_id` 和 `source_status`。产物采用不可变文件保存，并生成哈希和运行回执。

### `market_facts.json`

每条事实至少包含：

- `id`
- `metric`
- `instrument` 或 `series`
- `value`
- `previous`
- `change` 和 `unit`
- `source`
- `source_url`
- `source_time`
- `retrieved_at`
- `quality`

指数涨跌、收益率变化、行业排名和个股涨跌属于这一层。数字只能来自确定性数据源，研究模型不能覆盖这一层。

### `market_events.json`

每个事件包含：

- `id`
- `event_type`
- `title`
- `actual`
- `previous`
- `forecast`
- `revised`
- `source`
- `source_url`
- `source_time`
- `quality`

事件用于宏观数据、财报、公司公告、评级动作和美联储讲话。不存在的字段应省略，不能用模型补值。

### `research_bundle.json`

研究任务按窄任务拆分。每条结论至少包含：

- `claim`
- `evidence_ids`
- `sources`
- `confidence`，取 `confirmed`、`likely`、`possible` 或 `unclear`
- `status`
- `provider`
- `model`
- `prompt_hash`
- `attempts`
- `error_code`（失败时）

研究产物可以补充事件关联和解释，但不能修改 `market_facts.json` 的数值。原始模型输出只保存在内部运行目录，不进入公开页面。

### `daily_report.json`

日报产物包含各章节、引用的事实和结论、缺失来源、质量摘要、数据截止时间、产物版本和渲染信息。Markdown、HTML 和页面数据均从该产物生成，避免不同出口各自重新调用模型。

## 5. 研究任务与模型接口

研究任务按以下类型拆分：

- `market_driver`：解释指数、利率、美元和商品的主要变化。
- `top_movers`：为涨跌榜寻找公司级催化剂并判断证据强度。
- `macro`：整理经济数据、预期、前值和后续日程。
- `fed`：整理讲话、声明和政策窗口。
- `company_news`：整理公告、评级动作、财报和指引。
- `options` 与 `sellside`：作为后续可选任务，只处理有授权且可追溯的材料。

提供商通过统一适配器接入。Gemini、DeepSeek 等联网模型可以承担研究任务，Codex 或 Hermes 可以作为可选的多步研究 worker，但它们只写入 `research_bundle.json`，不拥有确定性事实。每个提供商都必须输出结构化 JSON，并记录重试、超时和错误码。

研究结果需要经过以下检查：

- 每个数字都能关联到事实或事件 ID。
- 每个结论至少有一个可访问来源。
- 来源时间不晚于报告截止时间。
- 模型不能把搜索摘要、推测或无来源内容写成确认事实。
- 没有足够证据时只能输出 `unclear` 或缺失说明。
- 研究结果中的事实与确定性数据冲突时，以确定性数据为准，并记录冲突。

## 6. 处理流程

```text
fetch
  -> normalize
  -> market facts
  -> market events
  -> research jobs
  -> evidence validation
  -> daily report
  -> render
  -> publish
```

建议提供以下 CLI 能力，命令名称在实施计划阶段最终确定：

- `dm market-facts`
- `dm market-events`
- `dm research`
- `dm daily-report`
- `dm validate`

每个日期和报告窗口需要幂等。重复运行应复用已成功的输入和产物，只重试失败的任务。无效产物不得自动发布。部署层继续负责定时触发、状态恢复、投递回执和失败告警。

## 7. 日报章节映射

日报首期按以下顺序组织：

1. 美股市场表现，包括指数、市场广度、行业、利率、美元、贵金属、能源和数字资产。
2. 市场驱动因素，包括已确认事件、可能驱动和仍不明确的部分。
3. 经济数据与美联储动态，包括实际值、预期、前值、讲话和未来日程。
4. 公司新闻，包括公司公告、财报、指引和评级动作。
5. 主要上涨个股，包括涨幅、公司、催化剂、来源和置信度。
6. 主要下跌个股，包括跌幅、公司、催化剂、来源和置信度。
7. 数据质量与缺口，列出未取得的字段、来源降级和未能确认的解释。

模板中的 GS、BofA、CTA、期权名义金额等内容只有在存在原始授权材料或可重算的完整数据时才进入正文，否则显示缺失或待核验。

## 8. 校验与质量指标

校验器至少检查：

- 数据源是否可用，是否超过 freshness 窗口。
- 所有事实是否符合截止时间和交易日历。
- 涨跌、收益率变化、曲线形态和排名是否可由输入重算。
- 结论的证据覆盖率和来源可访问性。
- 因果表述是否超过证据支持范围。
- 是否出现投资建议、目标价或未经授权的买卖结论。
- 是否存在重复事件、未来来源、孤立数字或模型编造的字段。

持续记录以下指标：来源可用率、事实完整率、结论证据覆盖率、校验通过率、提供商延迟和错误率、各章节完成率、失败重试次数、发布回执率。CI 增加协议样例、重放测试、来源时间测试和无效产物拒绝测试。

## 9. 分阶段发布

### 第一阶段：事实和协议

补齐收益率曲线、跨市场字段、行业和涨跌榜，建立 `market_facts.json`、`market_events.json` 与 `daily_report.json` 的 schema。先生成 shadow 报告，不改变生产投递。

### 第二阶段：研究任务

接入市场驱动、涨跌催化剂、宏观和美联储任务。在至少 5 到 10 个交易日内与当前日报并行，对比证据覆盖率、缺失率和错误率。

### 第三阶段：选择性生产

仅将通过校验的章节发布到 Feishu 和 Pages。研究提供商失败时保留确定性事实，并在报告中标出研究降级，不阻断基本行情日报。

### 第四阶段：授权研究

增加研究邮箱或 PDF 入口，保存原文哈希、作者、机构、发布日期和解析结果，再接入卖方研究、期权和 CTA 内容。

## 10. 验收条件

- 任意已完成交易日都可以按保存的输入重放。
- 指数、收益率和个股数字与确定性源一致。
- 每条市场驱动和个股催化剂都能追溯到事件或来源。
- 研究提供商不可用时，系统会降级并保留事实，不发布无证据解释。
- 每个公开产物都有 schema 版本、哈希、截止时间和运行回执。
- 发布失败可重试，错误产物不会覆盖上一次有效版本。
- Pages、Feishu 和本地 Markdown 使用同一份 `daily_report.json`。

## 11. 前置条件与风险

实施前需要确认 FMP 配额、Treasury/FRED 访问、Trading Economics 是否开通，以及 Hermes 是否具备运行研究 worker 的身份认证。DeepSeek 作为单 key 可选提供商，Gemini 继续使用现有 fallback。Codex 或 ChatGPT 定时任务适合做 shadow benchmark，不作为确定性数据源。

主要风险是来源变更、供应商限流、新闻因果不清和时间点污染。系统应优先输出可证实的事实，并明确区分已确认、较可能、可能和未确认的解释。
