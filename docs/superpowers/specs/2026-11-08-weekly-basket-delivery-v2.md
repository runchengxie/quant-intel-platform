# Weekly basket delivery v2

Approved scope: implement source changes and validate them through an owner-repository PR. Production activation, real messages, and resolution of historical uncertain deliveries remain outside this change.

The private canonical receipt schema is `weekly_basket.delivery.v2`. Text and image each move from `not_started` through durably checkpointed `inflight` to `accepted` or `uncertain`; an omitted image is `not_requested`. Acceptance requires process exit zero and a JSON object containing `ok: true` and `data.message_id` beginning `om_`. This proves CLI-reported acceptance, not that a human read the message. Inflight and uncertain attempts never retry automatically.

Retain existing provider idempotency keys. A canonical provider-target/week slot and stable process lock prevent caller date paths, sender changes, content changes, or image changes from creating another attempt. Bind the declared sender scope and target kind inside that slot. Require an explicit stable delivery state root for live API calls. The CLI uses its configured state root and accepts `--sender-scope`, defaulting from `WEEKLY_BASKET_SENDER_SCOPE`; this is operator-declared identity, not principal attestation.

Dispatch historical receipts by schema before validating them. Unversioned historical receipts retain their original bytes and status and cause `legacy_unverified` / `hold_no_send`, including historical failures and dry runs. Never invent message IDs or automatically migrate/resend them. Search the explicit legacy output root's date delivery paths for the same week, plus the requested receipt. Unknown or inconsistent state fails closed. A v2 mirror without canonical state also holds.

Freeze exact markdown and a private image snapshot before text begins. Verify image bytes against an immutable render manifest, and verify the frozen snapshot before and after image transport. A changed snapshot makes the phase uncertain even if the CLI returned an ID; retain that ID privately as evidence. Recovery after accepted text may send only an untouched, previously not-started image from the original snapshot. Any changed request holds.

Rendering publishes a complete private immutable bundle atomically, with a `weekly_basket.render.v1` manifest binding report identity and markdown/CSV/PNG sizes and SHA-256 hashes. Keep existing artifact aliases for readers. Render and delivery have separate stable-inode process locks. Use private directories (0700), receipt/lock files (0600), and image snapshots (0400). Durable checkpoints fsync their file and parent directory. These modes do not defend against a malicious process running as the same user.

Dry runs use a separate preview namespace for basket artifacts and new freeze state and never write live delivery state. They read authoritative previous-week baskets and reuse an existing current-week freeze without modifying it; an explicit override produces preview-only state. Keep public status vocabulary `sent`, `failed`, `not_requested`, and `dry_run`; `sent` requires every requested target and phase accepted, without empty-set success. Public projections expose verification and phase outcomes but omit routing IDs, provider keys, message IDs, and raw transport output. No manual reopen or resend operation is introduced.
