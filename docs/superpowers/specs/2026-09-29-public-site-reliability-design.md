# 公开日报网站的主题、浏览器回归与发布提醒

日期：2026-09-29

## 目标与边界

让公开日报在深浅主题、桌面与手机上保持可读；下载的 PNG 应与用户当前看到的报告图配色一致；发布检查失败或线上日报长时间未更新时，维护者能在 GitHub 看到明确提醒。网站仍只展示已审核的公开产物，不在公开 CI 抓取市场数据或使用模型、飞书等私有凭据。

本设计覆盖 `web/` 的静态网站、图片导出、公开 CI 和 Pages 健康检查。当天晚报数据 PR 的测试修复与合并沿现有发布流程处理，不属于新监控代码的前置依赖。其他 agent 的工作树、生产调度和私有发布器不在修改范围内。

## 方案选择

采用现有站点上的浏览器级测试，而非只扩充 HTML/CSS 字符串断言：后者不能证明按钮没有重叠，也不能证明 SVG 真实解析后的颜色。采用 GitHub Actions 和 GitHub Issue 提醒，而非新建外部监控服务或飞书机器人：这样无需新凭据和生产配置，代价是提醒依赖 GitHub 的运行与通知设置。保留现有快速单元测试，浏览器测试只覆盖少量关键路径。

## 图片导出

`downloadMarketChartPng` 不改动页面上的原始 SVG。导出时克隆 SVG，把原 SVG 通过 `getComputedStyle` 解析出的 `--report-bg`、`--report-ink`、`--report-muted`、`--report-track`、`--report-line` 写到克隆根节点，再序列化成独立 SVG、绘制到 canvas。解析失败时保留现有 SVG 变量的浅色 fallback，不能产生透明或无字图片。下载文件名、尺寸上限、URL 释放与错误提示保持不变。

单元测试先证明深色模式导出的 SVG Blob 含有解析后的主题值、原始 SVG 未被修改、失败仍释放 URL；浏览器测试再抽样核对页面图和下载 PNG 的背景像素。这个修复不改变报告事实、图表尺寸或数据契约。

## 浏览器回归

在 `web/` 中加入固定版本的 Playwright Chromium 测试和独立 `test:browser` 命令，使用仓库内公开样本构建后的 Astro 站点，不连接真实数据源。CI 在现有单元测试和网站构建之后运行浏览器检查，PR 不部署 Pages。

覆盖首页至少 390、768、1280 px 三档视口的浅色与深色状态：主导航与主题按钮的边界框不相交，手机上导航可滚动且不会遮住按钮；切换、刷新后主题状态保持；美股和亚洲报告 SVG 的计算背景色、文字色与页面主题相符。选择一张图验证 PNG 可下载且背景色与页面显示一致。失败时保留 Playwright trace/截图作为 PR artifact，不录制或上传私有数据。历史报告页只做一条加载与配色 smoke test，不建立脆弱的整页像素快照。

## 发布与过期提醒

新增仅从默认分支运行的公开 Actions 监控：

- `workflow_run` 观察 `Public website` 的完成结果。只对 `main` 构建失败或 `automation/pages-*` 日报 PR 构建失败发出提醒；不执行 PR 提交的代码，不展开未经转义的分支名到 shell 命令。
- 定时任务读取线上 `/data/reports.json` 与 `/data/market_daily_report.json`，在运行时重新计算亚洲晚报与美股日报的实际报告日期和生成时间；不能把构建时写入的 `/data/health.json` 当作实时结果。利用现有 `pipeline_health.py` 的日期校验语义，并单独校验美股日报字段。任一端点不可读取、时间戳无效或最后可用报告超过 96 小时则提醒。96 小时是保守的“需要人工核查”阈值，不声称理解美亚市场休市日，也不阻塞网页部署。
- 每类故障只保留一个带固定标签的 GitHub Issue；新失败追加简短状态与运行链接，恢复后自动关闭。Issue 不包含报告正文、密钥或原始响应。监控 workflow 本身失败时 Actions 检查保持红色，不能静默吞错。

监控使用最小权限：读取公开仓库与 Pages，只有创建/更新 Issue 的 job 获得 `issues: write`。定时任务可以手动触发验证；GitHub 原生通知的送达仍取决于仓库订阅设置，在运维文档中说明。长假可能产生“待核查”提醒，不能自动判为上游发布事故。

## 验证与交付

新行为按测试先失败、实现后通过的顺序开发。PNG 单元测试、Playwright 三档视口与主题测试、监控判定单元测试分别独立运行；随后运行 `web/` 全量检查、根仓适用门禁、`mkdocs build --strict` 和 `git diff --check`。PR 上浏览器测试及公开网站构建必须通过；合并后核对 Pages 部署成功、首页与报告链接可访问，并用 `workflow_dispatch` 验证健康监控的正常路径。故障提醒的创建/去重/关闭用模拟 GitHub API 测试，避免为测试向真实仓库制造告警。

## 非目标

不修改私有发布器、生产定时器、市场数据来源、报告内容和审核规则；不引入飞书凭据；不把 GitHub 96 小时年龄提醒解释为交易日历级 SLA；不清理其他 agent 的分支或 worktree。
