# Asia News Implementation Plan

> For agentic workers: use superpowers:executing-plans task-by-task after the user reviews this plan. Preserve the user's native, in-session execution preference.

**Goal:** Add independently reviewed, source-dated mainland China and Hong Kong news to evening report artifacts.

**Architecture:** Reuse existing market-news collection adapters but introduce a versioned Asia evidence envelope. Keep candidates separate from reviewed claims, bind translations to exact evidence, and let the static site consume only public reviewed artifacts. Japan and Korea are subsequent extensions, not enabled by this plan.

**Tech Stack:** Python, existing requests/provider adapters, JSON artifact contracts, TypeScript/Astro and offline pytest/Node/browser tests. No new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-10-02-asia-news-design.md` (user approved October 2, 2026).

## Global Constraints

- No scheduler change, production cutover, model provider change or test message.
- Raw documents, candidates, receipts and validation outputs remain outside repositories.
- The public site consumes only reviewed public artifacts, never provider responses.
- Date-only source precision remains date-only; retrieval time never substitutes for publication time.
- Models propose candidates, translations and summaries but cannot approve their own claims. Retain `collector_identity` on private candidates and reject review by that producer.
- Missing publication dates block same-day claims. Applicability includes `time_unverified` for date-only material on the cutoff day.
- Existing Tushare/Eastmoney authorization does not automatically authorize third-party news republication.
- Preserve legacy news consumers and the existing 07:00/19:00 personal delivery configuration.

## Review Focus

- A disclosure published after the report cutoff cannot appear as known-at-close evidence (Task 1).
- A holiday or incomplete local calendar must not be replaced by weekday arithmetic (Task 1).
- Cancelled, revised or duplicate documents need content-bound identities, not URL-only approval (Tasks 1–3).
- Host allowlisting, a successful request and structurally valid model JSON do not establish fact/rights approval (Tasks 2–3).
- Chinese and English must show the same reviewed numbers and dates, with missing translation explicit (Task 4).

### Task 1: Versioned evidence and time contract

**Files:** Create `src/daily_messenger/daily_report/asia_news_contract.py` and `tests/daily_report/test_asia_news_contract.py`.

**Interfaces:** Produce `AsiaNewsCandidate` (immutable dataclass), `validate_asia_candidate(payload: Mapping[str, object]) -> AsiaNewsCandidate`, and `candidate_applicability(candidate: AsiaNewsCandidate, *, cutoff: datetime, open_dates: Sequence[date], calendar_through: date) -> str`. Candidate fields include evidence ID, collector identity, market (`cn`/`hk`), source URL/publisher, source publication value and `time_precision` (`date`/`timestamp`), retrieval timestamp, optional event date, language, title, factual summary, source content SHA256 and optional revision-of evidence ID. Naive precise timestamps, missing publication dates, invalid hashes, invalid URLs and unsupported markets are rejected. Applicability returns `eligible`, `after_cutoff`, `holiday_context`, `calendar_unverified` or `time_unverified`.

- [ ] Write offline tests for aware timestamp and date-only precision preservation, naive timestamp rejection, missing publication date, future cutoff, invalid source URLs/hashes, midnight timezone conversion, holiday context and a calendar that ends before the source day. Literal expected statuses must be independent of the implementation.

- [ ] Implement the dataclass and validation. Retain the original publication value, normalize retrieval time to UTC, and compare precise timestamps in the source-market timezone (`Asia/Shanghai` or `Asia/Hong_Kong`). Date-only material on the cutoff day remains time-uncertain and is not claimed to have been known at close.

The callback is injected; the collector never calls a model or starts a scheduler. Candidate raw source bytes are retained by its caller in the external data root; content SHA256 derives from the actual bytes.

### Task 3: Independent exact-content review gate

**Files:** Create `src/daily_messenger/daily_report/asia_news_review.py` and `tests/daily_report/test_asia_news_review.py`; reuse the exact-content identity principles of `reviewed_research.py` without changing U.S. review manifests.

**Interfaces:** Produce `validate_asia_review(candidate: AsiaNewsCandidate, review: Mapping[str, object], *, cutoff: datetime) -> dict[str, object]`. A review requires independent reviewer identity, aware review timestamp, exact candidate/source hashes, approved claim text/hash, source URL, source-date verification note, fact verification note and rights/display note. An English translation is optional and carries its own exact claim binding. The function validates receipts, not the truth of reviewer attestations.

- [ ] Write failing tests for tampered source/candidate/claim hashes, revised sources, missing independent reviewer, self-approval, absent fact/rights notes, missing source URLs and changed English translations. Verify that a structurally valid candidate or allowlisted host alone cannot pass.

## Handoff and status

The user approved native in-session implementation. Tasks 1–3 are implemented and
committed. Task 4's optional refresh/import integration and bilingual presentation
are implemented. One independent whole-branch review found six material issues:
public field filtering, import rollback/repair, document supersession, supported
website staging, wall-clock fetch deadlines and translation review timing. Each
has a failing regression test and a fix; final complete gates and PR integration
are in progress. The original checklist is retained as the acceptance checklist,
not evidence of live acceptance.

Interface refinements: applicability requires both `calendar_from` and
`calendar_through`; collection uses `CollectionContext`; public projection requires
`report_sha256` and is bound to the exact Markdown bytes. Explicit revisions
supersede old candidates, identical document versions are deduplicated, and
conflicting unlinked versions fail closed. Fetch deadlines are enforced in a
main-thread Unix CLI with an exclusive process timer; unsupported execution
contexts fail closed rather than run unbounded.

Real-source acceptance is still pending. Synthetic offline receipts do not verify
disclosure facts, rights, reviewer identity, source freshness or local calendars.
No scheduler, production pin, provider configuration or delivery state has been
changed. Production cutover and no-send acceptance require a separate decision.
