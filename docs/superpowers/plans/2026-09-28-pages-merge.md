# 市场日报网页并入平台实施计划

对应设计：[市场日报网页并入平台设计](../specs/2026-09-28-pages-merge-design.md)。

1. 核对两个仓库的远端 `main`、未提交修改、生产 SHA、开放 PR 和 Pages URL。只在独立任务 worktree 修改，保留其他任务资源。
2. 在 platform 任务分支以 Git subtree 导入 Pages 到 `web/`。保持其内部路径、独立依赖、测试与公开快照。根项目的 Ruff、ty、pytest、coverage、打包边界明确排除 `web/`，由网页专属门禁覆盖。
3. 把 Astro 基址改成 platform 根路径，把 MkDocs 迁至 `/docs/`。合并 Pages 与文档 workflow，先构建日报，再在同一站点产物中构建文档。PR 不部署，`main` 只部署一次。
4. 对平台根门禁与网页门禁分别运行全部检查。离线构建后核对首页、`/docs/`、五期报告、数据与下载路径。创建并合并 platform PR，在新站核对桌面、手机、深色模式和内容哈希。
5. 在 deploy 独立分支修改两个发布器的仓库、路径白名单和脚本入口。扩充 smoke tests，验证 bot 只能修改 `web/artifacts/public/`，旧 pending 不被误用。合并 deploy PR 后准备稳定发布目录。
6. 核对 Codex 与备用模型生成路径，将需要密钥的回退逻辑保留在受控发布链路，不向平台公开 CI 注入密钥。逐项验证结果回执，未验证成功的回退供应商保持缺项提示。
7. 备份生产配置，停止两个网页发布定时器，核查机器人检出和 pending，切换稳定 deploy 与 platform 目录。逐个试跑发布服务，确认新站确实接收新增报告，再恢复定时器。失败则按设计回滚。
8. 在旧 Pages 仓库独立 PR 中把网站改为新地址跳转和迁移说明。验证后合并。旧仓库与历史发布目录先保留，不删除。
9. 最后核对新旧站、PR、CI、生产 SHA、调度状态、分支/worktree 与遗留问题，按仓库约定清理仅属于本任务的开发资源。
